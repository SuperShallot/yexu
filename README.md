# 页序

页序是面向 Codex 的前端设计与交付工作流，调用名为 `$reference-to-web`。适用于网页视觉审查、局部打磨、新页面设计、整页重做及设计稿实现。

新页面与整页重做依次完成需求确认、页面策划、设计出稿、用户选稿、前端实现和浏览器验收。选定的页面稿与确认后的需求共同作为制作和验收依据。设计阶段使用实际页面文案试排候选字体。验收阶段对照选定稿核对页面结构、字形和关键控件，在浏览器中复测交互状态与响应式布局，并删减重复或缺少明确用途的辅助文案。

## 安装与调用

将仓库克隆到 Codex 本地技能目录，并使用 `reference-to-web` 作为目录名。Windows PowerShell 安装命令如下。

```powershell
git clone https://github.com/SuperShallot/yexu.git (Join-Path $env:USERPROFILE '.codex/skills/reference-to-web')
```

如已安装同名 Skill，可将仓库克隆到其他位置，再按需合并文件。安装后，在新的 Codex 聊天中调用。以下为新页面任务示例。

```text
使用 $reference-to-web 制作面向首次到店顾客的 SPA 着陆页。
请先确认需求并拟定页面策划，提供设计稿供选择。
选稿后完成页面实现，并在桌面和移动视口中核对实际渲染。
```

## 工作流程

| 任务类型 | 处理方式 |
| --- | --- |
| 视觉审查 | 检查实际页面与相关状态，按影响程度记录问题、证据和改进建议。 |
| 局部打磨 | 沿用现有品牌和设计规范，修正指定区域，并复测相关视口与交互。 |
| 新页面或整体重做 | 确认需求与策划，提交设计稿供用户选择，按选定稿实现并完成浏览器验收。 |

## 测试结果

使用 Impeccable 公开的 Lumina 页面进行只读审查，并在副本中实施局部修正。以下数据来自 Microsoft Edge 离线浏览器测试，单位均为 CSS 像素。

| 视口 | 横向溢出（修正前 → 后） | 首屏主按钮底边距视口顶部（修正前 → 后） |
| --- | ---: | ---: |
| 1440 × 900 | 0 → 0 | 712 → 716 |
| 768 × 900 | 0 → 0 | 576 → 576 |
| 375 × 812 | 330 → 0 | 781 → 512 |
| 320 × 700 | 385 → 0 | 882 → 592 |

四种视口下，导航链接的最小高度均由 22px 提高至 44px。任务分流另以六条请求验证，覆盖只读审查、局部打磨、新页面、整页重做、按已选稿实现和范围未明确的请求。

Serenity Spa 公开样例用于验证需求梳理与策划阶段。试跑识别出的关键决策包括首屏的主要行动、疗程信息和预约入口。真实用户选稿后的完整交付，以及同一条件下与其他 Skill 的成品对照，仍待验证。
