# 页序

页序是一个前端设计与制作 Skill，调用名是 `$reference-to-web`。我想把做网页的顺序理清楚。先把需求问明白，再做策划和设计稿。等你选定满意的一版，再开始做页面，最后拿真实浏览器的效果来验收。

做《盐原回收站》时，玩法已经跑通，但一对照稿子，标题的字形还是差了一截，方向键也显得太简单。做《铁雾号》时，我又发现首屏边角的小字容易越放越多。这些都能在截图上看出来，所以页序把字体试排、关键控件对照和小字检查写进了流程。

## 怎么用

把这个仓库克隆到 Codex 本地技能目录。目录名使用 Skill 的调用名 `reference-to-web`。例如在 Windows PowerShell 中：

```powershell
git clone https://github.com/SuperShallot/yexu.git (Join-Path $env:USERPROFILE '.codex/skills/reference-to-web')
```

如果本机已经有同名 Skill，可以先把仓库克隆到其他位置，再按需要合并对应文件。打开新的 Codex 聊天，用类似下面的方式调用：

```text
用 $reference-to-web 帮我做一个面向第一次到店顾客的 SPA 着陆页。
先把需求和策划整理给我看，再出页面稿让我选。选定后实现，最后用桌面和手机宽度的浏览器截图对照。
```

页序按任务范围走不同的流程。

- **只审查**。看真实页面，指出具体问题、证据和改法。
- **局部打磨**。比如修手机导航溢出、按钮焦点或标题字形。沿用现有设计，修改后复测受影响的区域。
- **新页面或整页重做**。先核对需求，再做策划和出稿。等你选定一版可制作的页面稿，再按需求和设计完成网页并验收。

## 测试结果

用 Impeccable 的公开 Lumina 页面做了只读审查和局部修正。Edge 离线浏览器复测的结果如下，单位为 CSS 像素。

| 视口 | 横向溢出（修正前 → 后） | 首屏主按钮底边（修正前 → 后） |
| --- | ---: | ---: |
| 1440 × 900 | 0 → 0 | 712 → 716 |
| 768 × 900 | 0 → 0 | 576 → 576 |
| 375 × 812 | 330 → 0 | 781 → 512 |
| 320 × 700 | 385 → 0 | 882 → 592 |

四种视口的导航最小点击高度从 22px 提到 44px。另有六个请求用于检查任务分流，包括只给审查意见、直接修局部、从头做新页、整体换方向、按已选稿制作和范围不明的需求。

UI/UX Pro Max 的 Serenity Spa 样例也用来试跑需求策划。实际先卡住的是首屏该让人直接预约，还是先选疗程。这轮完成了浏览器测量、流程判断和策划试跑。完整的选稿到交付流程，以及不同 Skill 在相同条件下的成品对照，仍待验证。
