# 盐原回收站复盘

## 当时用过的东西

| 阶段 | 实际使用 |
| --- | --- |
| 早期版本 | 构页的案例检索与制作流程。原生 HTML、CSS、JavaScript 和 Canvas 等距投影。 |
| 重做方向 | Impeccable 的需求确认、构思抽选、三种构图比较、素材制作、机械检测和独立评审。Ponytail 用于控制实现范围。 |
| 视觉素材 | 内置 Image 生成构图稿，再重绘带峡谷、车辙和巡检车的干净场景图，压缩为 WebP。 |
| 页面实现 | 语义化 HTML 和 CSS。Three.js/WebGL 负责实时地形与驾驶，Canvas 提供平面地图降级。esbuild 打包引擎，Python 把素材与依赖嵌入单个 HTML。 |
| 字体和控件复修 | Barlow Condensed Black Italic、Noto Sans SC 的 WOFF2 子集。CSS 实心箭头、键帽立体边缘、键位标记和按压反馈。 |
| 验证 | Playwright 驱动 Edge。截图对照、离线加载、键盘与模拟触摸、WebGL 禁用、收集、返航和重开。复修时查了十个视口和焦点、按压、禁用状态。 |

## 暴露出的缺口

- 第一轮已跑通玩法，也做过独立评审。到用户看成品时才发现标题与设计稿的字面形态相差明显，方向键仍像默认小按钮。后来把英文标题的高度和窄斜比例单独对照，中文改用真正的重字重，方向键改为可辨认的实体键帽，再验证实拍和交互。
- 简报用宽幅场景图，驾驶用实时低多边形地形。独立评审发现两者的盐壳、车辙和进度带联系偏弱。改绘成双车辙和浅色盐壳，并把三枚信标与返航节点连进同一条任务带。

## 下次怎么检验改进

在送审前，把已选设计稿与实际首屏并排看，再单独对照标题、主控件和主要场景。给每个有影响的差异留一条可复查的证据。

| 要核对的地方 | 可用证据 |
| --- | --- |
| 标题是不是同一种视觉气质 | 原稿和成品的标题局部，真实字体状态，桌面和窄屏下的墨迹宽高、换行和裁切 |
| 方向键有没有廉价感 | 键帽静止、按下和聚焦的实际画面，触控目标尺寸，鼠标或触屏移动后可见的实际结果 |
| 简报与可玩场景是否连贯 | 两个阶段的同尺度截图，各自标出车、目标、路面和状态条 |
| 完整任务是否可玩 | 实际浏览器里的启动、移动、改变进度、结算和重开，附适用的离线或降级复测 |

用这些证据比较下一次制作中临近交付时的差距与用户反馈。一次案例只能说明工作流抓住了这次的漏项。
